# Smooth live page resizing

The user wants both sidebar-divider and native-window resizing to be buttery smooth. They explicitly delegated the choice of using a small prepaint buffer, accepting responsive layout briefly ahead of the visible edge, with no scaling or empty bar and an exact viewport after release.

The original paint-before-each-growth coordinator visibly stalls on responsive GitHub breakpoints. Shared cyclic stylesheet hints and bounded chrome geometry improve ordinary costs but do not remove that barrier. Retain those improvements and use a rolling native page-viewport buffer only during continuous drags.

- Capture visible page owners, native flags, original frames/parent sizes, split fractions and navigation metadata at drag start. Keep each web view's native autoresizing mask suspended through the drag.
- Prime extra painted coverage in the active resize axes at drag start. Use48–192pt adaptive lookahead, targeting0.18s of observed viewport velocity and a half-buffer refill threshold. These are implementation bounds, not a promise about unresponsive content.
- Commit pointer-driven window/sidebar geometry immediately while all pages' old painted coverage and any in-flight viewport cover that geometry. Prepare the next buffered viewport asynchronously with native WebKit child layout intact behind an explicit host clip; only consume new visible geometry after every split page presents. Never expose unpainted growth or scale existing pixels.
- Derive desired page geometry from a fixed drag baseline and the same PageResizeLayout/sidebar-fitting formulas as the UI. Account for split fractions. Do not accumulate overscan or native-parent deltas.
- On release, paint the exact requested viewport, publish the latest geometry, then restore native sizing and clear browser-owned style hints. Preserve sidebar detent, clamping, persistence, collapse, and accessibility behavior.
- Generation/owner guards reject late callbacks and programmatic root/frame replacement. A250ms paint watchdog restores flags and uses the existing bounded-fallback policy for truly unresponsive content. Closing, hiding, fullscreen, replaced pages and reversed drags must leave no frozen native state.
- Ordinary programmatic sizing retains the current exact-viewport path. Discrete sidebar closing retains its existing covered animation.

Verification retains strict WindowServer coverage at settled gutter+2pt, normal pageZoom and a final fixed-right marker at the exact endpoint. Continuous motion should target p95≤25ms, retain the existing≤80ms maximum and≤24pt step limits, and preserve every failed attempt. The already recorded146–153ms window stalls are RED evidence, not resolved by model tests. Foreground capture requires its actual owner; focus-interrupted runs cannot count as motion passes.

Implementation notes for the native owner:

- Use persistent per-page state for one drag, capturing original mask, child-autoresize flag, host clipping, web size, native parent size, navigation metadata and split fractions. Suspend the web view autoresizing mask, preserve native child autoresizing, and clip overscan at its host. Every prepared size must cover current and unacknowledged submitted native parents; every published size must fit both old paint and any in-flight preparation. This makes the host clip the visible authority without manually resizing WebKit internal children after its presentation callback. Restore only owned native mask/host clipping; preserve moved owners and original child-sizing behavior.
- Predict actual viewport from the fixed baseline, not the enlarged current web frame: original web width plus `(window width delta + old leading width - requested leading width) * split fraction`. Sidebar requests override only the requested sidebar width in the baseline navigation layout. Vertical deltas use the corresponding split fraction.
- While a smaller buffered viewport is in flight, geometry must fit both the last painted size and that in-flight size. This prevents reversal from exposing a newly smaller paint.
- Shrink retains existing painted coverage up to the192pt absolute lead ceiling before trimming back to the adaptive target. Scale that ceiling by each page's split fraction. Growth still refills below half its adaptive lead; a small shrink must not repaint merely because it exceeds the current48pt minimum target.
- Permit synchronous native geometry commits from a request once coverage exists, with a reentrancy guard for host layout callbacks. Maintain expected current window frame/root identity and reject unrelated programmatic replacements.
- On release during an in-flight paint, retain only the latest request. Once covered, commit it, prepare the exact viewport without lead, flush the actual final host layout once, and restore flags without applying a parent delta twice. Canceled/reparented views keep their new owner's frame/mask.
- Start priming at native resize begin / first sidebar gesture event. Infer native resize axes from the pointer's proximity to window edges and actual proposals; sidebar uses width only. Do not hold a wider layout for the entire drag: replenish and reduce the rolling buffer as the pointer moves.

Native inset evidence: a titled full-size window can give the web view a top safe-area inset (21pt on the measured machine). CSS viewport height excludes it. Hint/readiness conversion must use actual native safe-area insets and zoom. Buffered height must extend downward with the original page top gap preserved, and re-anchor as its host resizes; merely increasing an unflipped frame upward into the titlebar does not prepare extra CSS height. Restore the original relative frame at release/cancel.

Native sidebar publication: CPU samples show broad SwiftUI graph/layout work from every live-width publication while WebContent is mostly idle. Keep accepting every pointer proposal and applying the paint-coverage barrier, but coalesce covered sidebar widths to the latest value for the next native display callback. Use a60Hz display-link publication budget for this SwiftUI layout path; this bounds redundant graph work while preserving smooth visible movement. Flush the latest covered value at release before exact layout/paint reconciliation. Cancellation, page/root replacement, close/fullscreen and newer commands must discard queued stale values. Discrete reset/accessibility paths remain immediate. No sleeps, input pacing changes or motion/coverage assertion exclusions are permitted; the original actual WindowServer limits decide whether this improves the drag.

Metadata acknowledgment work is required only for a matching same-size submitted parent that would otherwise have no size-change callback. Ordinary size-changing SwiftUI updates use their existing native resize callback; do not schedule a second host layout for every width publication.

Frame presentation: the latest native clip capture passes all painted/window gates but still misses sidebarp95. Reconcile and display the owned native window once after an actual display-frame width publication so SwiftUI's deferred update lands in that frame. Never flush per pointer input, on an empty tick, after ownership loss, or in addition to the existing exact-release flush. Keep frame publication at60Hz and measure its actual layout cost; unchanged native bounds remain the acceptance gate.

Live width observation belongs at the geometry boundary that consumes it. Preserve the shared width preference and exact per-window fitting, but do not reconstruct the full BrowserWindow, its retained Library, Sidebar content, or inactive Space preview solely for a pixel change. Narrow geometry modifiers/layout shells may observe width while holding unchanged content. Responsive TopRow, AddressPill and Favorites remain live; pageResizeLayout metadata must still acknowledge the same native geometry. Keep the guarded frame flush while reducing this graph work, and verify real unshown native geometry, stable content identity/body counts and existing strict native capture limits.

Covered native window commits must honor a requested immediate display. After applying a painted frame with display enabled, ask the window to display its dirty views synchronously rather than only setting a deferred dirty flag. Do not add a root layout pass to each input; the native frame setter already updates geometry. Display-disabled requests stay deferred, and all paint/ownership admission remains before the commit. Measure the first visible frame and steady cadence with the original limits.
